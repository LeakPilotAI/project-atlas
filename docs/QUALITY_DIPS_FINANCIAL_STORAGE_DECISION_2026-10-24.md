## Minimum financial contract

One independently accepted new Quality Dips account/epoch, explicit hypothetical USD inception, disjoint resources and no legacy adoption. Initial MSFT/manual/long-only/USD100-entry/one-position parameters remain unaccepted proposals; their eventual enforcement belongs inside the serialized financial transition, not only a request builder. Required authoritative records: immutable inception/policy, stable operation/payload identities, source and position revisions, Decimal quantities/cash/costs, complete entry/partial/full exit facts, exact deterministic receipts, projection intents/acknowledgements, admission closure, report commitments and current-head continuity. A financial event and its canonical receipt must have one logical commit boundary. A canonical commit is not an acknowledged native projection or completed overall operation.

Freeze the accepted decimal precision, rounding, quantity/cash representation and cost-policy version before inception. Do not rely on mutable ambient Decimal settings or silently round/rewrite historical amounts. No floating-point accounting, unknown opening cash, invented equity or pooled legacy balances. Exact fees/slippage assumptions remain synthetic until accepted. All source-required reports must retain local calendar/timezone/cutoff and source commitments. Missing/contradictory records, pending projections, orphan publication, stale pins and capacity exhaustion refuse clean reporting/startup.

## A: exact proposed publication and read contract

Use one immutable file per operation, not in-place append to a single mutable log. Do not assume “append-only” names, a file extension or a local SHA256 proves authenticity. Root/epoch/issuer/current-pin enrollment is an accepted external prerequisite; this journal supplies none of it.

1. Under the reviewed native root-identity coordinator, require the accepted current pin, exact epoch/policy/resource identities, writer/incarnation admission, clock window, source/position revisions and no unresolved prior intent. No provider/process wait under that coordinator. Bound acquisition, record size and replay/capacity; refuse rather than overwrite, truncate or auto-rotate. F's existing prototype bounds are only starting test bounds, not an accepted retention policy.
2. Compute the next financial transition/receipt in memory from authenticated prior records using the frozen policy. Stable operation ID + exact payload returns an already acknowledged result without a new effect; conflicting payload or unknown commit does not execute again.
3. Exclusively publish and flush an intent binding operation/payload/previous accepted head and intended record digest. A failure poisons the instance and attempts a durable failure marker as in the repaired F primitive. Any incomplete allocation/publication is retained, never auto-adopted or deleted.
4. Exclusively create one record containing **command, financial result/receipt and previous-record binding**. Obtain file identity from that same creation handle before writing; flush bounded bytes and return that exact identity/digest. This requires a small reviewed `write_bound` extension: current `_write` returns no binding, so capturing an ID only after reopening an unknown path is not sufficient. Re-read with expected-ID `read_bound` before any result is trusted.
5. Flush an immutable commit descriptor binding that record's native identity/digest, operation, revision and prior head. Durably advance the accepted local handoff/current-head acknowledgement under the same protocol. Only a complete verified commit plus accepted current-head ack exposes the canonical event/receipt as acknowledged. This is **logical atomic visibility**, not a claim that multiple NTFS writes form one filesystem transaction.
6. Native projection and report acknowledgements are separate immutable records with their own identities/revisions. A financial commit with an unresolved required projection is COMMITTED_UNACKNOWLEDGED/UNKNOWN for the overall operation, not rolled back or reapplied. Failure after commit/before handoff is manual reconciliation, not “newest file wins.”
7. Restart obtains the current pin through accepted custody; validates expected native identities before payload, digest before decoding, canonical schema/sequence/parent/operation uniqueness, receipt arithmetic and complete intent/commit/ack continuity. Any newer intent, missing ack, unknown orphan or failed persistence blocks admission. A missing store never initializes itself. Report reads must hold a consistent committed-head view; no live-state/earlier-report mixing.

The accepted trust provider/custody is not an invented signing service: reuse the selected trusted-workstation operator policy and reviewed local handoff design after acceptance/enrollment. Local chains/keys under one rollback authority do not create independence. Same-account malicious code, administrators, external writers and coherent machine rollback remain outside demonstrated exclusion. Known restore/rollback must trigger manual baseline review. Unknown/unavailable authority always refuses. No guarantee of a newly durable failure marker exists when storage itself cannot persist it.
