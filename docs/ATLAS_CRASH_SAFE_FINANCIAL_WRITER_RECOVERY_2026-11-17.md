A previous process cannot resume after its exit. Durable generation comparison additionally rejects an old capability even when injected offline tests pretend the old identity is observable again.

A crash before PREPARED leaves no generation record. A crash after PREPARED leaves an unresolved fence and grants no writer. A crash after durable ACTIVE but before returning its ACK returns no success to the caller; only a **different** freshly proved owner, another genuine approval and a clean independent financial cut could attempt a later generation. The failed object remains terminal. Pending financial effects, source/report disagreement, abandoned mutexes, partial native image tails, unfinished orders, unknown funding and incomplete Stop outcomes are never auto-repaired. Read-only observation may itself refuse corrupt/incomplete history; fallback is not a promise to display unauditable balances.

Original operation scopes remain ≤5 seconds; original complete Stop target remains **≤8 seconds**. No browser, clock, ownership, three-reader socket or financial acceptance deadline was increased. Native Win32 query duration is checked and bounded outer owners remain mandatory; the Python check is not a claim that an unresponsive kernel call can be preempted safely.

Microsoft documents process-handle lifetime after process exit, PID lifetime, and native enumeration's buffer-completeness requirement.
