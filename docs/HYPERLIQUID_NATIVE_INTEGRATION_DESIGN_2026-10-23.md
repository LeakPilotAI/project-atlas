## Findings and bounded repairs

Four failing adversarial cases demonstrated that V2 read/replay validated local event digests and financial replay but failed to revalidate persisted request schema, execution-time quote freshness, exact revision types and duplicate JSON fields. A locally recomputed hash could hide semantically invalid receipts. These are integrity defects even though a local hash was never authenticated authority. Original four failures retained in logs/diagnostics/hl-review-repro.txt.

The fixture-only repair shares one strict request validator between admission and replay; validates exact event keys/integer revision; rechecks historical quote/source evidence relative to the recorded execution timestamp, not the current reader clock; and rejects duplicate keys/nonfinite JSON throughout baseline, operation, event and ledger comparisons. It changes no V2 event layout, identity algorithm, valid legacy record or native writer. Existing source pins and pending-operation refusal remain mandatory. Valid previously committed events remain readable and acknowledged retries do not execute another fill. All four cases now refuse. Two additional integration cases connect the existing disposable writer coordinator to V2 acknowledgement/reporting: successful drain and an unacknowledged committed fill. Unknown callbacks cannot replay; late writer admission fails before mutation; incomplete drain blocks wrapper reporting. Actual source positions remain OPEN/ENTERED in both cases.

Residual limitations, not PASS: two stores do not commit atomically; cooperative locks do not exclude independent writers; a baseline status is not fresh native state; same-user or coordinated rollback can rehash both stores without independent witness; caller receipts are not authority. Identity uses exact immutable serialized economic fields, so equivalent decimal spellings can yield different identities on a new import. Do not silently recanonicalize existing V2 IDs: require a reviewed, versioned adoption mapping. Decimal precision/rounding context and currency units must be explicitly accepted for runtime accounting. There is no actual V2 native writer, migration or operational recovery path today.

## Proposed native contract — implementation requires separate approval

1. Introduce one logical canonical selected-lane position event authority behind an explicit facade, rather than two independently authoritative financial stores. The physical storage choice remains subject to D1 protected identity/publication acceptance; do not adopt path-based SQLite or a new VFS as accepted by this document. Reuse reviewed components after acceptance, not a new security framework.
2. New entries require an already accepted startup/run authority,explicit manual request ID,manual confirmation,source epoch,1USD risk,max3positions and existing3R session stop. Source-bound timestamped prices remain required. No automatic mirror/prediction/Discord or provider connection is authorized. A risk-reducing exit is distinct from entry admission; a closed entry gate must not deadlock orderly exits.
3. Assign a canonical shared position ID at initial durable entry and persist its native UUID/setup association once. Never derive an operational ID from mutable mark data or a caller-chosen new namespace. V2 exact-byte identity remains readable; adopt it through an immutable reviewed mapping if appropriate. Decimal normalization changes require an explicit identity-contract version, not reinterpretation of existing IDs.
4. Define record_exit(position_id,operation_id,expected_position_revision,quantity,price_evidence,session_id). Validate ownership,remaining quantity,quote freshness,version and replay semantics before effects. Keep position revision distinct from global source revision. Stable operation IDs are retained for the complete accepted history; bounded caching must not forget replay protection. Commit exit event and its canonical financial result together where the accepted storage supports it. Return a durable revision/digest receipt only after the required durability boundary.
5. Manual snapshots,API caches,cash movements,reports and dashboards are projections with an applied canonical revision. An acknowledged event is never executed again to repair a projection. A missing projection acknowledgement is RECONCILIATION_REQUIRED; no fabricated close,deleted position or automatic uncertainty clearing. Recovery may rebuild a projection only after independent source/exclusion and revision-bound recovery approval; this milestone implements none of that authority.
6. Partial positions stay OPEN/PARTIALLY_CLOSED with explicit initial,closed and remaining quantities. Zero remaining is asserted only after committed fill/finalization and accepted projection reconciliation. Native-facing FLAT additionally needs all writers drained and source-complete reconciliation. Administrative INTERRUPTED must remain a separate lifecycle state. Fee/slippage policy and USD versus venue settlement units must be frozen in the accepted source contract; funding/margin cannot be silently zero-filled.

## V1 compatibility and historical adoption

Keep original V1 journal/snapshot bytes and historical reconstruction untouched. No dual V1 full close at a final partial price. Read retained V1 whole-close history using its original cost/R semantics; preserve recorded4dpR separately from derived exact-decimal currency. New V2 events use an explicitly separate schema/namespace and a version-aware facade. Old raw readers remain available for retained V1 artifacts, but cannot report current V2 positions/accuracy/FLAT without migration to the projection or explicit UNAVAILABLE status.

An adoption proposal must pin original source hashes,record counts/versions,per-position native IDs,all partial/full/correction records,fees,clocks,currency and independent complete inventory/witness. Reject duplicate setup associations,ambiguous manual-versus-journal records,missing opening balances,interrupted closes and unknown revisions. Produce append-only adoption records mapping original evidence to canonical IDs,with a separate discrepancy report and independent reconciliation before any authority changes. No heuristic symbol/side matching or synthetic zero opening account. B1 remains blocked; no actual archive or migration was accessed here.

## All-writer lifecycle acceptance contract

Freeze release/run/process/writer/resource identities and trusted incarnations before entry. Register manual API,refresh/alerts,canonical journal,marks/adaptive exits,projection,cash/report/lifecycle writers and any admitted standalone callbacks. Exclude nonselected mirror/coach/equity/diagnostic/shadow paths with a verified denial,not assumptions. Missing,foreign,restarted,duplicate or uncertain actors refuse startup/clean completion.

Use distinct gates: close new-entry admission; drain already admitted financial operations; retain a narrow owned shutdown-exit/report phase; close final mutation admission; verify every acknowledgement,source revision and process/child lifetime. A drain marker cannot stop pending admitted exits from committing, nor authorize new entries. Specify lock order admission -> canonical event -> projection publication; never hold an admission transaction while waiting for callbacks or process exit. No deadline increases. Timeout/disconnect/crash produces INCOMPLETE/TIMED_OUT/UNKNOWN truthfully and preserves durable intent/positions. A parent exit is not all-writer quiescence, and process observation is not ownership authority.

Only after valid prices,remaining liquidation,independent fill/quantity/cash reconciliation,report persistence and all-writer evidence may owned service shutdown be considered. Never stop Docker Desktop/Engine or unrelated resources. Restart must refuse corrupt/pending/mismatched revisions or incomplete writer history; review exact-helper exit and recovery authority separately. No fixture receipt becomes production permission.
