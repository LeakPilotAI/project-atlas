## Native API references and qualification limits

The directory parser follows the documented [FILE_ID_BOTH_DIR_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_both_dir_info) layout. [GetNamedPipeInfo](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-getnamedpipeinfo) supplies buffer measurements on original read ends. [PeekNamedPipe](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe) documents synchronous/multithread blocking qualifications; offline capacity tests do not prove a hard native bound. [CoCancelCall](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-cocancelcall) requests cancellation; this implementation still requires completion of the retained worker and does not treat a cancellation request as completed cleanup. These references support design choices, not evidence that Windows APIs were executed successfully here.
