## Why this work replaces the failed approach

The host Windows 11 Time service intermittently reported stale NTP data or adjusted the wall clock at faster than Atlas's existing monotonic allowance. A persistent standalone phase-correction fix improved short-interval slew but did not deliver a consistent 180-second Windows-Time-based admission. The Microsoft high-accuracy host profile was separately trialed, empirically rejected, and fully rolled back. We will **not weaken Atlas's financial timing requirements** or run recurrent system-wide resyncs.

Atlas can instead derive UTC directly from *two separate external NTP endpoints* and advance it with the Windows high-resolution monotonic QPC counter. This removes **W32Time service / system UTC wall clock as a time authority**; it does **not** remove dependence on the host hardware oscillator, network/DNS, or external public time providers.

- Each response yields *server-derived* UTC at the local monotonic midpoint and a conservative uncertainty radius incorporating network round trip, root dispersion, root delay and timing margin. The two independently named peers must agree within a strict **250ms** difference and overlapping uncertainty intervals; neither one can substitute for the other. This is **unauthenticated public NTP**, not NTS, TLS, signed UTC or authenticated provider identity.
