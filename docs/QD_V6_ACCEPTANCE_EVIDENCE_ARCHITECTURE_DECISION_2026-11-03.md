## B — Proposed alternative active-listener contract

**PROPOSAL ONLY / NOT APPROVED / NOT IMPLEMENTED.** A possible research direction is an independently queried native socket witness tied to the actual retained listening object and exact launch lineage, while leaving three-reader cleanup intact. A differently labelled owner report or HTTP response is insufficient.

Windows documents socket sharing through `WSADuplicateSocket`/`WSASocket`; a separate witness process could potentially query the same underlying object. This is a documented mechanism, **not a demonstrated equivalent Atlas acceptance contract**. Sharing also means socket state is shared and the socket stays open until the last descriptor closes. The API does not itself provide a read-only access boundary between the participants. [Microsoft WSADuplicateSocket](https://learn.microsoft.com/en-us/windows/desktop/api/winsock2/nf-winsock2-wsaduplicatesocketa).

Before the sole operator could approve such a contract, its design and disposable validation must establish:

1. Exact native source/recipient identity, retained original handles, ancestry, creation times and PID-reuse refusal; a PID or a self-reported socket number is insufficient.
2. Binding to the actual listener used by the installed host, exact address/family/port and complete competing-binding coverage, including wildcard and dual-stack conflicts. Duplicating one socket does not prove this namespace property.
3. Independently obtained native socket state, authenticated coordination and bounded freshness; no fabricated observer acknowledgement or conversion of TCP state 0.
4. A controlled trust boundary for any duplicate socket capability. A purported read-only witness must not silently gain unreviewed listener mutation or I/O authority.
5. Deterministic closure of every extra descriptor **before** original Stop/drain verification, plus crash, malformed handoff, wrong recipient, stale witness, retained-duplicate, competing-listener and restart tests. Duplicates must not keep the port open or weaken eight-second Stop.
6. The unchanged three-reader cleanup/process/Job/handle rules, browser verification, financial isolation and original deadlines.

The current immutable support launcher creates the server inside the installed child and publishes identity/URL, not a socket-sharing handoff. Introducing this mechanism would require reviewed support/IPC source and new immutable support-package identities, receipts and acceptance; its effect on application-release pinning also requires assessment. Existing support files cannot be patched in place. This is not a small observer parsing correction. No complete equivalence proof exists, and this direction may fail the competing-binding or capability-boundary requirements. It is **not recommended for immediate implementation**.
