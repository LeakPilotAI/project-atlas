# Atlas R20 successor — exact original QD native archive capacity (2026-11-13)

## Actual original-format blocker to months-long PAPER

The `NativePersonalResearchArchive` uses the selected original `NativePersonalCoordinationImages`, whose immutable bounded protocol has `MAX_REVISIONS = 128` **including the once-only genesis image**. The source archive image's own logical revision must be at most 127 and its native revision equals logical+1. These are original on-disk identity, ACL, intent/commit/ACK and page bounds; do **not** increase constants to hide exhaustion, replace historical files, reset an epoch, or manufacture a new `root_id`.

The financial current-source readers enforce a Quality Dips source-cut freshness of 30 seconds; the issuer and original archive must publish more often than that for continuous current-source admission. At an idealized 30-second publication cadence, there is capacity for just **127 x 30 = 3,810 seconds (63.5 minutes)** after genesis. A single uninterrupted **6.5-hour** stock market session needs **780** original source publications, and a hypothetical 90-day always-on forecast would require **259,200**. Those calculations are *best-case write counts*, not a guaranteed session lifetime: network/verification/overlap may require additional publication attempts. Fewer writes are allowed if no financial source admission is needed; there is no automatic safety benefit in allowing stale source information to authorize an order.

## Code and verification added

The existing `scripts/observation_runtime/personal_research_archive.py` now has a **strict read-only** `capacity_readonly(horizon_seconds, publication_interval_seconds)` method. It requires an original fully readback/authority-verified `archive.current()` head, checks that the genuine native `images.remaining_commits()` exactly equals `128 - head.native_revision`, checks logical/native epoch correspondence, and rereads the head to reject concurrent or substituted state. It fails closed for an out-of-bounds/noninteger forecast, forged remaining counts, corrupted native ACK, foreign source enrollment, unavailable authority or modified native-format limit. The returned packet is a forecast only, never a source issuer, account, financial root write, trading grant or automatic epoch handoff.

New tests in `tests/test_personal_research_archive.py` prove the 127/780/259200 write forecasts, no writes during repeat reads, and native/authority/future claims that fail closed. A new `test_original_native_handle_bound_capacity_readback_does_not_create_a_successor` in `tests/test_personal_research_archive_native.py` exercises **real original Windows-native** immutable image roots, validates actual file hashes and live native readback before and after one disposable source publication, and ensures the capacity forecast cannot mutate it.

The **real Windows-native test scope** was restricted to a uniquely named child of `D:\Work\Project Atlas\logs\diagnostics`; it ran successfully with **10 passed**, including the new real-native handle-based test. Its entire disposable test scope was removed immediately after tests; it never touched the 12 original financial roots under `D:\Atlas*`. The other in-memory archive/current-source tests passed **106**, with nine native-only cases skipped absent the deliberately separate test-scope requirement. This does not demonstrate the installed R20 source-archive rollover or real PAPER financial issuer; the code is an **uninstalled source-only successor change**.
