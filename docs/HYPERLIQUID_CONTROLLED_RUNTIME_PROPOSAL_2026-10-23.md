### Command and acknowledgement contract

Operation ID is durable for the accepted history and binds the complete semantic payload. Identical acknowledged retry returns the original receipt without another event,fill,cash movement or projection mutation;conflicting reuse refuses. A pending operation never blindly re-executes its callback. New entries need the accepted trusted admission path and current risk proof;exits use a distinct risk-reducing phase authority,not a fabricated entry-control pass.

Receipt:operation ID,payload digest,source epoch/schema,canonical global source revision/event IDs,position revision,financial result digest,durability outcome and required applied-projection revisions. A successful API response requires the full documented acknowledgement boundary. Canonical commit known but required projection acknowledgement missing => RECONCILIATION_REQUIRED/UNKNOWN,not full success or automatic compensation. Receipt retrieval can report confirmed canonical facts without authorizing replay or new entry.

Per-position revision protects quantity updates;global source revision orders all events;projection acknowledgements separately record their applied source and position revisions. A reader returns a bound cutoff/schema/epoch and freshness state. Missing or stale projections cannot report FLAT,complete cash or clean shutdown. Background projection recovery requires fresh source/exclusion evidence and accepted recovery authority;N1 supplies none. ## 5. Exact shutdown protocol within existing deadlines

1. **ENTRY_CLOSE:** durable phase transition closes new entry and background trading admission before acknowledging shutdown. Reject duplicate/stale phase commands;retain stable shutdown operation ID. Do not close the authority needed to finish already-admitted work.
2. **FINANCIAL_DRAIN:** settle/observe all pre-close entry/fill/cash operations and acknowledgements. Freeze complete original inventory and remaining quantities. Pending/unknown callbacks => INCOMPLETE/UNKNOWN;no blind replay. Preserve a read-only,owned quote path if shutdown exits need fresh prices.
3. **SHUTDOWN_EXIT:** admit only exact remaining-quantity simulated exits under the accepted shutdown phase;no entries. Validate source-bound prices at each command. Use existing cost policy and atomic event/receipt boundary. Stale/missing prices retain positions;do not substitute last-known prices or administrative INTERRUPTED exits.
4. **FINAL_FINANCIAL_DRAIN:** close all further financial mutation admission. Verify source cutoff,all quantities/fill IDs,position/source revisions,cash movements/fees and projection acknowledgements independently. Stop quote producers/connections only after required exit evidence is collected;verify actual drain rather than cancellation alone.
5. **REPORT_AND_FINAL_DRAIN:** publish immutable daily report at that cutoff under a report-only gate. Bind timezone,currency,opening evidence,unresolved exceptions and applied revisions. Persist report acknowledgement,then close report/metadata writers and verify the complete roster has no active,pending,unknown or replaced member. N1's cooperative report lock is not all-writer/native exclusion.
6. **OWNED_BACKEND_SHUTDOWN:** persist run-bound final outcome,then bounded connection/task cleanup. COMPLETE requires every required step and final acknowledgement;any missing process/writer/report evidence is UNKNOWN/INCOMPLETE. Timeout stays TIMED_OUT even if a late task later completes. Preserve original exceptions and evidence;logging or process exit cannot substitute for success.
7. **MANAGER/DEPENDENCIES:** manager verifies exact child identity and run/release/outcome before ownership cleanup. Only separately authorized Atlas dependencies may stop after independent backend/writer exit proof;Docker Desktop/Engine and unrelated services remain running. Unresolved shutdown preserves evidence/fences and startup refusal. No generic process termination or manual reset.

Backend shared shutdown budget remains20.0s (main.py/ShutdownReport);manager owned API wait remains30s,existing readiness wait180s. These are ceilings,not added sequential allowances. Explicitly budget report/liquidation inside the accepted existing envelope;failure to fit is an acceptance blocker,not permission to raise deadlines. Existing manager/runtime wiring does not implement this staged protocol yet.
