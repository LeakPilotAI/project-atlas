## Authority, resources and startup

The native observer supplies current PID, Windows creation FILETIME and executable image; identity is observed using supported Win32 self-process APIs and checked again before/after admitted reads. This is identity evidence, not independent ownership, parent/command/SID acceptance or shutdown authority over another process.

The separate acceptance interface is `acceptance.lease(context, trusted_now)`, yielding `check(context, trusted_now)`. Context binds read-only mode, account, epoch, enrollment digest, host instance and exact observed process identity. Accepted custody independently leases current native resource pins/high-water for every financial read. The existing native reader verifies actual source/projection/report root and file identities before trusting bytes and never constructs writer/recovery-capable store guards. Freshness, UNKNOWN, report/source consistency and rollback refusal remain enforced by the existing read capability. The acceptance lease must independently enforce genuine read-service scope, resource/exclusion continuity and trusted time across the operation; a boolean config label is not acceptance.

Missing authority, mismatched account, stale/UNKNOWN current pins, absent resources, changed process identity or unaccepted read-service scope refuses before listener allocation. ## Ownership and shutdown

Readiness requires a real HTTP health response matching host instance, process identity and read-only mode after financial preflight. Session verification additionally checks account/epoch and current acceptance. Duplicate Open reuses only a verified active session; another host cannot claim the same composition context. A stopped/failed context is retired; a restart needs fresh accepted composition and a new host identity, never a recycled ready receipt.

The read-session bridge interface is `open_read_only_session()`, `verify_read_only_session(ready)`, `close_read_only_session(ready)`. The Python owned host implements it; the Windows module consumes an accepted bridge/proxy implementing it. Windows checks exact selected-page loopback URL/mode/host and process metadata plus a strict boolean verification result before opening the default browser. Browser-open failure invokes owned-session cleanup; failed close keeps bridge/session references and cancels GUI closure. No process is killed by PID, name or port, and no unrelated/Genesis process is enumerated or stopped.

New read-host bounds reuse 15-second readiness and 12-second close waits; existing operational lifecycle deadlines are unchanged. The read server uses bounded graceful shutdown. A blocked I/O/request need not terminate merely because cancellation was requested; a join timeout retains ownership and reports failure rather than disposing an active listener/thread. None of this grants operational financial shutdown authority.
