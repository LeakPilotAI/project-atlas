## Defect and authoritative input
- Existing `backend/app/adapters/hyperliquid.py::_paper_funding_observation` rejected any `fundingHistory` entry unless its public `time` matched a UTC hour at the exact millisecond.
- Official Hyperliquid perpetuals `fundingHistory` response example reports event time `1683849600076`, **76 milliseconds after** UTC hour `1683849600000`. Source: <https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint/perpetuals> under **Retrieve historical funding rates**. The strict original parser therefore rejected an officially documented shape, which is one plausible **cause class** of the previously observed BTC funding-history `ValueError`; the original raw rejected response was not retained, so its exact failure cause remains unproven.
- Funding from `fundingHistory` supplies a public *rate* and premium, **not the accepted historical settlement oracle, personal account tier or funding cashflow**. Provider event times must not be silently backdated into a trade decision.

## Actual code changes and bounded safety contract
- `backend/app/adapters/hyperliquid.py` accepts **one, and only one, consecutive event per UTC hour**, whose `time` lies between its exact hour boundary and **+30,000 milliseconds**, inclusive; each accepted event must also be at or before the independently supplied actual observation clock.
- The existing financial `PerpSourcePlanner` already refuses a due settlement after its 30-second recovery window (`now > at + 30`). Keeping this publication limit **no longer than** that window prevents a 24-minute-late provider print from being treated as on-time.
- Each output record **preserves the original provider event time** as `provider_event_at_ms`, the bounded delta as `publication_delay_ms`, and the canonical UTC-hour settlement cut as `settlement_at_ms`. The planner's existing exact-hour match remains unchanged. The output still sets `settlement_oracle=null`, `settlement_evidence_complete=false`, `financial_execution_authorized=false`, and `startup_authorized=false`.
- Retained refusals: missing or duplicate hours, out-of-order rows, wrong coin, malformed rate/premium, nonfinite or excessive rates, publication before hourly boundary, event after observation, and publication later than 30 seconds. **No historical oracle is synthesized**, funding is not silently assumed zero and funding-rate evidence alone still cannot settle a PAPER position.

It now tests an actual **30,001-ms violation**, preserving meaningful denial. `tests/test_perp_source_order_native.py` updated one *guarded synthetic financial fixture* to carry 76-ms provider event lag; the guarded test has not been accepted/run under an approved AIP-06 harness.
