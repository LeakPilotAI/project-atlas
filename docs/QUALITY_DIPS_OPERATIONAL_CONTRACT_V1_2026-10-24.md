## Authentication and native interfaces

1. An independently accepted composition injects enrollment, current custody, clock, native resources, process observer and read-service acceptance. None is loaded from CLI, environment or arbitrary JSON files.
2. Separate read-service acceptance authenticates the exact QD_OP_READ_SERVICE_CONTEXT_V1 before preflight/listener work. Observed self identity is not ownership authority.
3. Current custody `lease(enrollment, now)` provides a complete operational bundle. `lease.check(bundle, now) is True` must independently authenticate enrollment, accepted account scope, issuer, clock, session, actual current high-water, exclusion and rollback continuity **before any resource read** and again before return.
4. Native port must expose `read_operational(enrollment, current)` and `verify_operational(enrollment, current, documents)`. The latter must independently check native handle identities, immutable bytes, complete financial replay/audit and projection/report consistency. Both are mandatory; no fallback to `read_verified`, FS2_TEST_PIN_V1 or existing disposable financial engines exists.
5. Only a verified read is normalized into the existing QD_COMMITTED_PROJECTION_V1 / QD_SELECTED_INCEPTION_VIEW_V1 **UI presentation** shapes. Operational policy_schema remains explicit. This reuse changes neither source records nor historical disposable schemas and confers no financial authority.

A malicious injected Python callable cannot be sandboxed by a schema. Injection of arbitrary objects is not independent authentication. Actual custody, clock, enrollment and native adapter implementations require separate security acceptance. A coherent locally recomputed rollback cannot be detected from local hashes alone; a fixed independent high-water custodian must reject it.
