## Diagnosis and preserved evidence

The original R7E46W `publish_synthetic_marker` calls `os.link(marker.pending, ACCEPTED.synthetic)` after flushing and fsyncing the pending marker. Under the current managed Windows sandbox, that exact previously failing test reproduced `PermissionError: [WinError 5] Access is denied` at `os.link`. The source and destination are in the same directory, and `stat().st_dev` matched. A new disposable probe in that directory also received WinError 5 for a hard link, while a same-directory `os.rename` succeeded; renaming onto an existing target returned WinError 183 and did not replace it. The strongest supported explanation is an operation-specific hard-link restriction for this test identity. The exact sandbox/Windows policy responsible is not independently identified; this is not evidence that all filesystem permissions or production destinations are suitable. No ACL, security policy or privilege was changed.

The original source/test bytes were copied before modification to `logs/diagnostics/workspace-market-20261023/stage22-hardlink-diagnostics/` (SHA-256 source `59e031290c400c7933a59492a372cf58b852fb977ad469a6a0fb400d13ec1a83`, test `9a4c47450d372d84440ab012515da58e7c3fadbe7c76138f154bf41560f41d11`). The original failing pytest output is retained as `original-failure.txt`; the successful portability probe is `portability-probe.jsonl`. The preliminary neighboring journal suite stalled on its first isolated case and was interrupted; it has **no acceptance count** and was not promoted to a pass.

## Minimal repair and guarantees

The synthetic marker publisher now validates an exact lower-case SHA-256 digest and uses Windows `os.rename` from the fsynced pending file to a new marker in the **same directory**. It uses neither `os.replace` nor an overwrite option. On non-Windows systems the original hard-link experiment remains. Under this Windows test identity, a completed rename exposes the prepared marker, a replay refuses with `FileExistsError`, and a failed rename leaves `marker.pending` for diagnosis. Two concurrent publishers produced exactly one marker. Mocked permission denial and unsupported/cross-volume moves refused while preserving pending evidence. No alternative syscall is attempted after a permission failure.

This establishes only same-directory synthetic namespace behavior under the current filesystem and identity. It does **not** establish directory-entry fsync, power-loss persistence, secured/encrypted destination ACLs, behavior on another volume or filesystem, continuous writer exclusion, or a real usable backup. Existing sandbox hard-link denial remains a documented environmental limitation; the original acceptance test now exercises the justified Windows rename path without skipping it.

## Synthetic archive and scratch restoration

`synthetic_rehearsal.py` accepts only six exact, bounded `synthetic:` byte fixtures; it cannot discover or read Atlas databases. It creates a new operation directory and exclusive fixture files, flushes/fsyncs each, writes a deterministic manifest with per-fixture SHA-256 and a separate manifest digest, verifies both, and leaves the archive `SEALED_UNVALIDATED`. Restoration verifies the archive before creating a separate, new scratch directory and checks copied bytes. A marker labeled `ACCEPTED.synthetic` is published only after exact-byte scratch readback. The test covers corruption, missing and extra members, rehashed but incomplete manifest, short writes, interruption, existing destinations, nested/same restore path, repeatability, replay, concurrent publication, marker tampering, permission denial, and unsupported move. Every incomplete attempt retains its partial files; none creates a success marker.

The manifest digest is stored beside the manifest and is **not an independent authenticity witness**; a party able to alter both can recalculate it. The synthetic prefix and small size bound reduce accidental use on real payloads but are not an authorization boundary. No PostgreSQL/Redis payload, host journal, protected PAPER record, credential, real volume, Docker container, or production backup destination was read or modified.
