## Rollback and interruption semantics

Rollback appends a new immutable selection receipt. It restores only an explicitly referenced earlier verified selection, after re-verifying that release's actual receipt, native identity and current bytes. It never rewrites an earlier record, deletes a release, rewinds financial custody, replays an inception or starts a service.

There is currently no verified native previous-selection marker: desktop shortcuts point to workspace observation scripts. The first selection therefore has a verified empty-selection baseline. Explicit rollback of that first selection can restore UNSELECTED, which causes the installed launcher to refuse. This is not falsely labelled restoration of the old fca runtime or a desktop-shortcut rollback. Desktop references stay outside this selector and unchanged in this execution.

An interrupted stage without atomic publication refuses after restart. An abandoned Windows writer refuses. A complete durable publication followed by loss of the caller acknowledgement is resolved by read-only receipt/identity verification; the original attempt is not claimed successful and its operation cannot be blindly repeated. No uncertain operation is reset/overwritten.

Current-instance history rollback is detected. Across a whole same-user/disk rollback, local hashes and files are not independent anti-rollback custody. The caller must supply the exact accepted head for launch; startup never selects whichever historical version happens to be found. This residual personal-use limitation remains explicit.
