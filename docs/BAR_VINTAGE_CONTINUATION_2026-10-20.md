## New working functionality

`scripts/observation_runtime/bar_vintages.py` provides an explicit opt-in receipt
store on a caller-owned isolated SQLite connection. It never migrates or changes
the original ReplayStore tables; default conflicting-bar refusal is unchanged.
Each normalized fixture receipt is append-preserved with sequence, predecessor
and digest. A transactional retained head detects missing records/tail loss
relative to that head. Exact retries deduplicate; contradictory same-time receipts,
new backdated receipts, asset identity changes and malformed/corrupt state refuse.
Unchanged later confirmations are retained separately from value corrections.

BEGIN IMMEDIATE serializes cooperating receipt writers. Receipt rows and the head
commit together. Success is returned only after commit; before/after-commit fault
injections show truthful failure and idempotent retries. Reads use one SQLite
snapshot. Unrelated pending caller transactions are refused without commit or
rollback. Store capacity is 10,000 receipts per symbol; no silent truncation.

Projection selects only receipts available by the decision clock. A correction or
reversion changes the selected value from its receipt onward; unchanged repeated
values retain their first receipt in that value run. Original evidence is never
overwritten. Replay reuses the existing descriptive analyzer/reference/calendar
checks for every explicit clock, preserves unavailable/refused denominators and
limits receipt-decision work to 200,000. Analysis identity and receipt-audit identity
are separate. A later confirmation can change audit evidence without inventing a
new price action. Future receipts/reference corrections cannot alter earlier cases.

The existing exporter now has an explicit `ATLAS_VINTAGE_REPLAY_REQUEST_V1` mode.
It produces source receipt chunks, per-decision audit artifacts, replay JSON,
scriptless HTML and an exact-byte browser envelope under a new manifest schema.
Verification reconstructs inputs and replays every decision. Old V1/V2 requests,
manifests, fixtures and output bytes remain compatible. Partial publication keeps
evidence and never reports success. Paired comparisons use vintage audit identities
when present and preserve their complete planned denominator.

The isolated `create_vintage_app` factory exposes GET-only receipt-history/research
and scriptless HTML for an explicit symbol universe. It copies reference vintages,
uses no-store/CSP headers and returns sanitized refusal on inconsistent storage.
It has no server launch command and is not mounted in production Atlas.

The offline frontend verifies exact payloads with native WebCrypto, checks selected
research via the existing strict validator, independently verifies portable receipt
audit commitments and reconciles counts/heads. Failed replacements/rendering and
late verification cannot restore stale views. Actual CLI and ASGI-produced fixtures
are regenerated byte-for-byte by Python and consumed by JavaScript.

## Limits and market readiness

This is logical consistency in caller-supplied synthetic evidence. Receipt clocks,
provider completeness and original data truth are not independently authenticated.
The head shares the SQLite rollback domain; rollback/deletion of both database and
head cannot be detected without an independent retained commitment. No protection
against privileged writers, malicious namespace substitution or full-machine
rollback is claimed. SQLite's configured commit boundary is not hardware power-loss
certification, Windows directory durability, backup or restoration acceptance.

Completed minute-bar closes are not executable quotes, official closing-auction
prices, split-adjusted daily datasets or dividend-inclusive returns. No conversion
to an AFI DAILY_CLOSE series is implied. No forecasts, fills, P&L or authority are
created. Normal market-calendar/availability limitations still apply.

Offline data flows and scriptless artifacts are locally usable. Main Atlas/dashboard
startup remains blocked by the protected lock; no current runtime census or native
browser visual acceptance occurred. Actual authorized live collection still needs
provider/exchange/session entitlements, automated-use/storage/display/historical
rights, credentials checked without disclosure, verified wire budgets and vendor
timestamp/delay/adjustment behavior, then separately approved read-only runtime
acceptance. A credential or successful fixture test proves none of these.

Shortest safe live path: establish a permitted equity/ETF feed and session scope,
close existing budget/admission prerequisites, then authorize bounded observation-
only acceptance with PAPER/prediction/live/Discord actions denied. No bypass.
