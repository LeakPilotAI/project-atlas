# R7E47S isolated observation runtime

This package is inert on import. It cannot launch Atlas, Docker, a provider, a broker or Discord. It is not installed in production startup paths.

## Contracts

`contracts.py` accepts only explicitly enrolled SYNTHETIC_ONLY fixtures. A retained FixturePin binds canonical manifest bytes, directory/file identities and bounded release/environment content hashes. The manifest names release, runtime, state, journal, cache, assets, environment, configuration, dependency, database, volume, port, session, source and process identities plus disjoint development resources. No candidate may enroll itself as production authority.

`bootstrap.py` requires fresh subject/manifest/attempt-bound ownership, admission, dependency, storage, provider-rights, provider-budget and development-isolation evidence. Five seconds is the inclusive synthetic freshness bound. Missing/stale evidence yields UNKNOWN; conflicting/invalid evidence yields BLOCKED. ADMITTED always has production_start_authorized=false.

Synthetic direct, API and background dispatch all enforce capabilities before invoking the fake handler. Live orders, PAPER creation/management/bootstrap, prediction opens, pending execution, Discord, background trading, recovery clearing, production startup and migration are denied. Only bounded observation, research and typed history are available. There are no production FastAPI routes or transport adapters here.

`history.py` exclusively initializes disposable evidence, retains file pins, serializes cooperating writers, preserves append-only hash-chained session records and reuses the existing independent journal commitment. Durable start precedes fake runtime admission; interrupted/pending/corrupt history refuses new sessions. Stable event identities prevent semantic duplicate retries. No reset, truncation, recovery grant or uncertainty-clear operation exists.

The test harness explicitly enrolls a fixture, constructs a pinned contract and retained history, supplies SyntheticWorld facts, evaluates, and starts only an inert object. NextStartupSelection selects an accepted/approved candidate in memory after that object stops; it never deploys.

## Scope limitations

This is not an OS sandbox. DevelopmentWorkspace guards its own writes; arbitrary code running under the same unrestricted account can bypass it. Native acceptance proves a restricted fixture token cannot write protected fixture assets/state while it can write the positive-control development file. It does not prove the actual development process is restricted.

Portable repeated path/identity/hash checks do not exclude all malicious concurrent namespace substitutions. The existing SQLite commitment retains its path-based VFS/sidecar and rollback limitations; it is fixture history, not recovery authority. No independent full-machine rollback anchor, Windows directory-fsync guarantee, power-loss certification, backup or restore acceptance is established. Virtual freshness does not bound uninterruptible filesystem calls. Manifest/environment fixtures are not a packaged complete Atlas release. External Docker writers and privileged actors remain outside scope.

Run only the isolated tests; no real startup instructions or production enrollment are provided.
